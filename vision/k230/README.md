# K230-A 钢球视觉与坐标上报

K230-A 将摄像头中的钢球位置转换为主控可用的毫米坐标，并显示球位与目标参考点。MSPM0G3507 根据这些数据控制摆杆；K230-A 不直接控制电机。系统任务与成果见[项目总览](../../README.md)，主控如何消费数据见[主控说明](../../firmware/H_BallBalance_MSPM0G3507/README.md)。

本目录公开 [main.py](main.py)。检测模型和 `deploy_config.json` 未包含在仓库中，需与相应 K230 / CanMV 环境配套准备。

## 从图像到球位

| 阶段 | 程序处理 | 输出 |
| --- | --- | --- |
| 检测与筛选 | 调用检测模型，保留指定画面区域内的钢球候选，检查置信度 | 球中心、候选数量及置信度 |
| 坐标换算 | 根据固定机械原点或本轮动态捕获点计算相对位置 | 正方向远离合页、负方向朝向合页的球位 |
| 状态上报 | 按发送时间门限组成二进制 UART 帧 | 坐标、有效标志、序号和时间戳 |
| 本地显示 | 绘制钢球、目标点和参考线，显示最近发送数据 | 供操作人员观察的球位与捕获反馈 |

程序以已知 1 cm 钢球的检测框宽度估计运行时像素比例。固定模式锁存参考锚点后采用固定换算；动态模式继续使用逐帧比例。这些换算针对现有机构和安装位置，换摄像头或改变安装后需要重新核对。

### 固定机械 O 点：T3～T5

首次有效识别后建立默认原点；随后连续 15 帧单目标有效识别用于锁存固定参考线。默认黄点建立与固定坐标准备完成是两个阶段，不能以“看到黄点”代替有效坐标检查。

固定坐标由零点和正向参考锚点计算：

```text
x_base(cm) = (x_zero - x_ball) × 5 / (x_zero - x_plus_5)
```

正方向保持该结果。负方向先经过程序中的分段映射，再按已有毫米测量关系反算：

```text
旧 K230 输出 y(mm) = 0.6898 × 实际刻度尺位置 x(mm) - 2.8626
x(mm) = (y + 2.8626) / 0.6898
```

O 点保持为零；O 到首个实测点 `-10 mm` 连续连接，之后使用反算关系。绿色 `-5 cm` 线由同一换算反定位，固定锚点锁存后不随检测框宽度继续移动。实现入口是 `fixed_offset_cm()` 与 `correct_fixed_negative_offset_cm()`。

### 动态捕获零点：T6

T6 先在主控侧等待单球候选稳定，再由 PB27 发起带序号的捕获请求。K230 从收到请求后开始收集数据：连续 15 个有效单球中心、置信度不低于 0.65，且 X/Y 两个方向的像素极差均不超过 3 px，才分别取中值作为动态零点。捕获窗口最长 2 秒。

成功回执只说明 K230 已建立目标。主控还要匹配请求序号，清除捕获前视觉状态，并在 500 ms 内连续收到 3 帧合法新动态坐标，才进入 READY；操作人员再次确认后启动任务。失败或超时允许重试。

动态坐标使用“捕获中心减当前球中心”乘运行时比例，不套用固定模式的负向修正。收到恢复默认原点命令后，取消捕获并切回固定模式。

## 接线与通信协议

```text
K230 GPIO9  / UART1_TXD  → MSPM0G3507 PB3 / UART3_RX
K230 GPIO10 / UART1_RXD  ← MSPM0G3507 PB2 / UART3_TX
K230 GND                ↔ MSPM0G3507 GND
```

使用 115200、8N1；接线前确认 TTL 电平兼容并共地。以下命令均采用同一帧结构，校验为从 `command` 到载荷末尾的字节累加低 8 位：

```text
A5 5A command length payload checksum
```

### 钢球状态帧 `0x10`

固定 13 字节：

```text
A5 5A 10 08 flags sequence x_lo x_hi conf_lo conf_hi time_lo time_hi checksum
```

| 字段 | 当前源码含义 |
| --- | --- |
| `flags bit0` / VALID | 球坐标有效；未识别、坐标准备未完成或超出范围时不置位 |
| `flags bit1` / CALIBRATED | 本帧坐标换算条件成立且运行时比例可用；不是独立的实物标定验收结果 |
| `flags bit2` / MULTI | 存在多个合法候选框 |
| `flags bit3` / TARGET_CENTER_VALID | 默认固定原点或动态捕获原点有效；**不专指按键捕获成功** |
| `sequence` | 8 位序号，循环递增 |
| `x` | 有符号 16 位小端，单位 0.1 mm，有效范围 ±150 mm |
| `confidence` | 0～1000 的置信度整数 |
| `time` | K230 毫秒计数的低 16 位 |

发送逻辑在每次推理后检查 20 ms 时间门限，实际频率受推理和循环耗时影响，不能据此认定端到端更新周期恒为 20 ms。无有效球位时仍发送状态帧，`VALID=0`，坐标和置信度为零；主控必须先检查有效标志，不能把零值当作钢球位于 O 点。

### 捕获与恢复命令

| 命令 | 帧内容 | 作用 |
| --- | --- | --- |
| 捕获请求 `0x90` | `A5 5A 90 01 request_id checksum` | 从请求到达后开始捕获；新请求替代未完成请求 |
| 捕获结果 `0x11` | `A5 5A 11 04 request_id status center_x_lo center_x_hi checksum` | 返回请求序号、状态和横向零点像素 |
| 恢复固定原点 `0x91` | `A5 5A 91 00 91` | 取消未完成捕获、清除动态目标、切回固定模式 |

结果 `status=0` 表示成功；`1` 表示超时且没有形成稳定窗口；`2` 表示出现过不稳定窗口后超时。失败结果的 `center_x=0`。主控准备任务时使用 `0x91`，只有 T6 再发起动态捕获。

## 屏幕与部署检查

屏幕显示最近实际发送的 `X:+xx.x mm` 或 `X: NO BALL`，并显示有效状态、置信度、帧序号、UART 发送结果和捕获进度。红点表示钢球，黄点表示当前目标；固定模式显示橙色 `ACT:+5cm` 和绿色 `ACT:-5cm` 参考线，动态模式隐藏固定参考线。

部署需要：

- 与当前脚本接口匹配的 K230 / CanMV 运行环境，包括 `libs.PlatTasks`、`libs.PipeLine`、`libs.Utils` 与 `machine` 模块；普通桌面 Python 无法直接运行此程序。
- 设备目录 `/sdcard/mp_deployment_source/` 中的 `deploy_config.json` 及其引用的检测模型。
- 与项目相符的摄像头、显示和机构安装位置，以及独立核对过的 UART 接线。

准备环境、模型和配置后部署 `main.py`。先静态放球检查 O 点、正负坐标、无目标状态及参考线，再验证 `0x91` 切换、T6 捕获/超时/重试和主控 READY 门控；最后才将坐标用于电机闭环。源码中的系数不能直接视为另一套机构的标定值。
