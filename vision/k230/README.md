# K230-A钢球识别主程序

## 文件

- `main.py`：K230开机运行的钢球识别与UART上报程序。
- 模型和`deploy_config.json`继续放在
  `/sdcard/mp_deployment_source/`。

## 接线

```text
K230 GPIO9 / UART1_TXD  -> MSPM0G3507 PB3 / UART3_RX
K230 GPIO10 / UART1_RXD <- MSPM0G3507 PB2 / UART3_TX
K230 GND                <-> MSPM0G3507 GND
```

参数为115200、8N1。通电前必须确认两端TTL电平兼容并共地。

## 双向通信协议

所有帧统一为：

```text
A5 5A command length payload checksum
```

`checksum`为从`command`到payload末尾的所有字节累加后取低8位。

### 钢球状态帧V1

固定13字节：

```text
A5 5A 10 08 flags sequence x_lo x_hi conf_lo conf_hi time_lo time_hi checksum
```

- `flags bit0`：识别有效。
- `flags bit1`：已完成正式像素—毫米标定。
- `flags bit2`：当前存在多个合法候选框。
- `flags bit3`：已经用捕获键建立本次任务目标零点。
- `sequence`：每次发送加1，按8位自然回绕。
- `x`：有符号16位小端，单位0.1 mm；远离合页为正，朝合页为负。
- `confidence`：无符号16位小端，范围0～1000。
- `time`：K230 `ticks_ms`低16位，小端。

未识别到球时仍按20 ms发送心跳帧，但`VALID=0`、`x=0`、
`confidence=0`。MSPM0必须忽略无效帧中的坐标。
有效X限制为`-150.0～+150.0 mm`；动态估算超出该范围时改发无效帧。

没有动态捕获点时使用固定机械O点。用户已经确认黄色O点和现有橙色
`+5 cm`位置准确。固定模式连续取得15帧单一有效球后，一次性锁存黄色O点和
橙线像素。两点先生成不再随球框变化的基础坐标：

```text
x_base = (x_zero - x_ball) × 5 / (x_zero - x_plus_5)
```

`x_base>=0`时原样输出，因此黄色O点、全部正方向坐标和橙色`+5 cm`均不变。
负方向先保留当前K230坐标生成结果，再按用户用毫米测得的关系反算实际位置：

```text
当前K230值 y = 0.6898 × 实际刻度尺值 x - 2.8626（x、y单位均为mm）
实际值 x = (y + 2.8626) / 0.6898
```

该拟合只用于负方向。黄色O点固定为`0→0`；从O点到首个实测点`-10 mm`
连续连接，从`-10 mm`起严格使用上述反算式。实际`-50 mm`对应修正前的当前
K230值`-37.3526 mm`，绿色`-5 cm`线据此锁存，不再关于O点等距镜像。
锁存完成后两条显示线不会随球框宽度变化。T6动态捕获模式不使用固定锚点或
上述负向修正，仍按当前1 cm钢球检测框宽度逐帧换算。

### 捕获目标零点

TI端PB27捕获键产生以下请求：

```text
A5 5A 90 01 request_id checksum
```

K230收到请求后才开始采集，避免把按键前的缓存帧用于标定。连续收集15个
置信度不低于0.65的单目标中心；X、Y两个方向的像素极差都不超过3 px时，
分别取中值作为屏幕上的固定原点。最长等待2秒，新的请求会替代尚未结束的
旧请求。TI协议仍只需要并返回横向`center_x`。

K230返回：

```text
A5 5A 11 04 request_id status center_x_lo center_x_hi checksum
```

- `status=0`：成功，`center_x`为本次目标中心像素。
- `status=1`：超时且没有形成稳定窗口，`center_x=0`。
- `status=2`：出现过不稳定窗口后超时，`center_x=0`。

TI只接受与当前等待序号相同的结果，成功后才进入READY。成功标定后，
位置计算以捕获中心为零点，图像左侧仍为正、右侧仍为负；状态帧
`flags bit3`同时置位。

### 恢复固定机械O点

MSPM0准备任一任务时先发送：

```text
A5 5A 91 00 91
```

`0x91`是零载荷命令。K230收到后取消正在进行的捕获、清除旧动态目标，
并恢复固定机械O点。T3、T4和T5直接使用该固定原点；只有T6随后允许使用
PB27发送`0x90`，捕获任意指定位置。当前源码连续取得15帧单一有效球后锁存
固定机械O点、准确的`+5 cm`位置及毫米公式修正后的`-5 cm`位置；`0x91`后显示这组固定
标定，T6捕获成功后改为显示本次动态捕获黄点。固定锚点不跟随钢球移动，
UART帧格式和`flags bit3`定义不变。

## K230屏幕

屏幕左上角显示最近一次实际发送的内容：

- 第一行距离使用52号大字：`X:+xx.x mm`或`X: NO BALL`。
- 其余信息使用22号小字：有效状态、置信度、帧序号、UART发送结果、
  捕获进度/结果、零点像素和请求序号。
- 捕获过程依次显示`CAP:WAIT n/15`以及`OK`、`TIMEOUT`或`UNSTABLE`；
  回执发送失败时显示`TXERR`。
- 不再绘制模型检测方框、框上置信度和ROI边框；当前钢球中心显示为半径5
  像素的红点。
- 捕获成功后，固定原点显示为半径8像素的黄点。钢球仍位于原点时红点覆盖
  黄点中心形成红心黄环；移动钢球后红点移动、黄点保持固定。
- 动态黄点在收到`0x91`后清除，并立即切回已锁存的固定机械O点黄点；
  K230重启后需先识别到一次钢球以重新取得比例并锁存固定黄点。
- 固定模式连续取得15帧单一有效球并完成锁存后，橙色`ACT:+5cm`线使用用户
  确认的准确位置；绿色`ACT:-5cm`线使用公式中实际`-50 mm`对应的当前K230
  值`-37.3526 mm`反定位。两条线只覆盖有效ROI；T6模式不显示。
- 参考线与UART固定模式坐标共用同一组锁存像素，球框宽度继续变化时不会
  漂移；重新上电后仍需重新完成15帧锁存。
