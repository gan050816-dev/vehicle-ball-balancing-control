# MSPM0G3507 主控固件

本工程把底盘循迹、钢球位置控制和执行器保护组织到同一套任务流程中：接收灰度、编码器和 K230-A 球位，计算双轮速度及摆杆控制量，再通过 OLED 显示运行、完成或故障状态。

项目任务与阶段成果见[项目总览](../../README.md)。本文说明当前公开源码的行为、连接和使用方式；早期独立调参程序见 [task2-legacy](../task2-legacy/README.md)。

## 当前任务行为

| 任务 | 控制内容 | 结束方式 |
| --- | --- | --- |
| T2：循迹一圈并停车 | 八路灰度识线与双轮速度闭环，后段减速并确认 A 线 | A 线连续确认后制动；20 s 未完成则超时故障 |
| T3：静止换点 | 从 O 点到 `+5 cm`，再跟随负向参考到 `-5 cm` 附近 | 满足位置与速度稳定条件后结束跟踪；当前诊断路径无总运行超时 |
| T4/T5：固定位置平衡 | 小球保持固定机械 O 点，底盘循迹；滚球 PD 叠加底盘加速度前馈 | 不自动识别 B/A 终点，也不定时停车；由复位或安全故障停止 |
| T6：指定位置平衡 | 先捕获本轮球位为零点，再复用移动平衡控制链 | 与 T4/T5 相同 |

OLED 菜单仅有 T2～T6。T1 的 K230-B 图传独立运行，不与主控交换控制数据。

### 底盘控制

[底盘服务](src/services/line_drive_service.c)以 10 ms 为控制节拍，处理灰度偏差、速度规划、编码器反馈、速度 PID 和安全制动。定时中断累计待处理节拍，实际控制在主循环执行。

| 参数 | 当前源码值 |
| --- | --- |
| T2 巡航 / 接近目标速度 | 410 / 100 mm/s |
| T2 减速开始 / 开放 A 线识别 | 13.50 s / 14.00 s |
| T2 A 线确认 | 至少 4 路灰度有效，连续 3 个控制周期 |
| T2 最大差速 / 每周期差速变化 | 270 / 40 mm/s；前进时为内侧轮保留 20 mm/s 目标余量 |
| T2 加速度 / 加加速度上限 | 800 mm/s² / 2000 mm/s³ |
| T4 目标速度 / T5、T6 目标速度 | 208 / 230 mm/s |
| T4～T6 加速度 / 加加速度上限 | 300 mm/s² / 800 mm/s³ |

以上是控制设定，不是实测圈时或实际轮速。T2 的终点识别和速度规划分别有时间门限，不能把减速开始当作到达终点。

### 钢球与摆杆控制

[T3 控制器](src/tasks/task3_controller.c)先以 `-20.50°` 固定角起步，再由预测与 PD 控制接管。新鲜原始位置进入 `+46.5～+52.0 mm` 即切换负向参考，不附加该帧速度门限；负向参考到达 `-50 mm` 后，连续 5 帧位于 `-52～-47 mm` 且滤波速度绝对值不超过 20 mm/s 才完成。完成后主程序停止连续跟踪，不继续保持目标位置。这些判据不能证明满足原赛题的 5 秒指标。

[T4～T6 控制链](src/tasks/balance_drive_run.c)共用位置/速度 PD、底盘加速度前馈和 120 ms 视觉新鲜度检查。T6 的捕获点在控制器中对应零坐标。OLED 记录本轮最大正、负滤波偏差；超出 ±10 mm 本身不会触发故障，验收仍需查看实测轨迹。

## 操作流程与硬件连接

### 按键和准备过程

| 功能 | MCU 引脚 | 用途 |
| --- | --- | --- |
| 选择 | PA15 | 循环选择 T2～T6 |
| 捕获 | PB27 | 仅 T6 在允许捕获时使用 |
| 确认 | PB23 | 确认机械下限、选择任务、从 READY 启动 |
| 复位 | PA29 | 停止并解除步进使能，制动底盘，返回 HOME |

1. 断电时人工将齿条放到机械下限；上电看到 `HOME / RACK LOW` 后按确认。
2. 主控停止、使能、清零并移动到水平位置，反馈到位后进入任务菜单。
3. 选择任务并确认。T2 进入 READY；T3～T5 进入放球等待，将钢球放在固定 O 点，连续收到 3 帧合法新鲜视觉后进入 READY。
4. T6 先等待单球候选稳定，提示允许捕获后按 PB27。捕获成功回执之后，还须在 500 ms 内连续收到 3 帧合法新动态坐标，才进入 READY。
5. READY 状态下再按确认才启动并开始计时。启动前视觉失效会返回等待；运行中故障或按复位会停止执行。

捕获等待允许重试；T3～T5 的放球等待不计入任务运行时间。T4～T6 无自动停车，需要现场观察终点并人工复位。

### 接口分工

| 对象 | 外设 / 引脚 | 配置 |
| --- | --- | --- |
| X42S 步进电机 | UART1：TX PA8 / RX PA9 | 115200、8N1，接收中断 |
| K230-A | UART3：TX PB2 / RX PB3 | 115200、8N1，接收中断 |
| OLED | I2C0：SDA PA28 / SCL PA31 | 400 kHz |
| 八路灰度 X0～X7 | PB20 / PA24 / PB25 / PB26 / PB10 / PB14 / PA17 / PA7 | 直接 GPIO，黑线低电平有效 |
| 底盘方向 / PWM | PB17 / PB19 / PA16 / PB24；TIMG0 PA12 / PA13 | 双轮方向与 PWM 输出 |
| 左轮编码器 | TIMG8 PA26 / PA27 | 硬件 QEI |
| 右轮编码器 | PA14 / PA25 | GPIO 中断译码 |
| 预留 UART0 | PB0 / PB1 | 保留 9600、8N1 配置，无接收中断，当前无业务收发 |

UART2 未配置。陀螺仪业务和蓝牙调参未接入当前主工程；历史陀螺仪解析源码仍保留。

当前机械下限绝对伸长约 22.5 mm，软件将它定义为 0 mm；水平软件位置为 14.9 mm，正常命令范围为 1.0～28.5 mm，硬边界为 29.5 mm。参数定义见 [stepper_service.h](src/services/stepper_service.h)。这些坐标依赖人工下限确认，电机编码器也不能替代独立位移测量。

首次烧录或上电时断开电机主电源或架空车轮，先确认方向、编码器符号、机械范围和复位制动，再加载机构。

## 通信与故障处理

- **视觉链路：** UART3 中断只写入 128 字节接收队列；主循环检查帧格式、校验、序号、位置与新鲜度。K230 的固定原点、动态捕获和字段定义见[视觉端说明](../../vision/k230/README.md)。
- **执行器链路：** UART1 使用独立 64 字节队列。步进服务处理 X42 版本、命令应答、状态和实时位置；回平等离散动作须同时满足到位标志与位置误差条件。连续跟踪保留最新目标，并检查执行器跟随。
- **等待与运行：** 菜单、放球、捕获、READY 等人工等待页允许单次健康查询超时后重试；回平和正式运行恢复严格超时检查。明确的失能、堵转和机械越界仍会触发故障。
- **日志状态：** [main.c](main.c) 中 `TASK3_USB_TTL_LOG_ENABLED=0`。CSV 格式化和发送代码保留在关闭的编译分支内，当前不会从 PB0 输出 T3 日志，也不能通过蓝牙工具在线调参。

运行页每 2 秒刷新 OLED，状态切换与故障提示立即刷新；任务计时仍按主循环经过的毫秒数推进。降低显示频率不能证明消除了显示刷新对控制调度的影响。

将本目录作为现有 CCS 工程导入，核对 SDK、编译器与板级配置后构建。[`.syscfg`](H_BallBalance_MSPM0G3507.syscfg) 是板级配置源；生成的驱动配置、启动文件和链接文件由工具链生成，仓库不提供可直接证明当前硬件行为的烧录产物。

在本目录运行纯逻辑测试：

```powershell
& 'C:\Program Files\PowerShell\7\pwsh.exe' -NoLogo -NoProfile -File .\tests\run_all.ps1
```

已有整理记录为 **18 项通过、1 项失败**。`task3_controller` 在命令跟踪状态转换断言处未通过，全量脚本会在此停止；其后的 `gyro_parser`、`task_menu`、`app_controller` 曾分别补跑通过。这不是全量通过记录，也不替代 CCS 构建或硬件验证。
