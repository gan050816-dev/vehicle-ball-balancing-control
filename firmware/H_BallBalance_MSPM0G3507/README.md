以下T3 CSV实现仍保留在`main.c`的编译期关闭块中，当前固件不会执行或输出：

```text
t_ms,x_mm,phase
100,-0.3,1
200,1.2,1
```

历史格式中，`x_mm`是控制器实际使用的滤波位置；视觉无新鲜数据时为`NA`。
`phase`取值为
`0`未启动/等待视觉、`1`正向固定角驱动、`2`正向PD接近、`3`负向轨迹跟踪、
`4`回水平/视觉暂失。当前不再连接或使用USB转TTL采集该日志。

## K230-A通信协议

K230-A程序保存在`D:\eletri\k230\main.py`。物理连接为：

```text
K230 GPIO9 / UART1_TXD  -> MSPM0 PB3 / UART3_RX
K230 GPIO10 / UART1_RXD <- MSPM0 PB2 / UART3_TX
K230 GND                <-> MSPM0 GND
```

钢球状态帧固定13字节：

```text
A5 5A 10 08 flags sequence x_lo x_hi conf_lo conf_hi time_lo time_hi checksum
```

- `flags bit0`表示识别有效，`bit1`表示正式比例标定完成，`bit2`表示多候选，
  `bit3`表示K230已经建立本次任务目标零点；
- `x`为有符号16位小端数，单位0.1 mm，远离合页为正、朝向合页为负；
- `confidence`范围0～1000；
- `time`为K230毫秒计数低16位；
- 校验为从命令到载荷末尾的8位累加和。

K230在每次新推理后按20 ms发送门限工作。未识别时仍发送心跳，但`VALID=0`、位置和置信度均为0；
主控不会把该坐标当成物理O点。主控只在UART3 ISR中写入128字节环形队列，
解析和范围检查均在主循环进行。有效X限制为`-150.0～+150.0 mm`。

T6先不限时等待连续3帧有效、单候选且置信度不低于0.65的原始球候选，稳定后
OLED才提示允许捕获。捕获键通过PB2发送
`A5 5A 90 01 request_id checksum`；K230收到请求后才开始收集15帧单目标中心，
像素极差不超过3 px时取中值作为新零点，并通过`0x11`结果帧返回请求序号、
状态和零点像素。主控只接受当前等待序号；成功回执到达后清除捕获前的固定O点
视觉状态，并继续等待连续3帧捕获后的合法动态坐标，才调用
`AppController_CaptureSucceeded()`进入READY。K230捕获窗口为2秒，TI等待回执
上限2.5秒，成功回执后的新帧另有500 ms上限；任一阶段失败都停留在CAP并允许
重试，不进入FAULT。发送采用非阻塞检查和100 ms超时，不在主循环无限等待。
当前K230通过1 cm钢球框宽动态估算比例，坐标和比例有效时状态帧置
`CALIBRATED=1`。

准备任一任务时，主控先通过PB2发送零载荷帧`A5 5A 91 00 91`，使K230取消
未完成捕获、清除旧动态目标并恢复固定机械O点。固定模式在旧图像中心坐标上
使用`0.2 cm`几何偏移并持续显示固定机械O点黄点，再对固定模式输出增加
`+0.3 cm`；两项合计把旧关系`y=x-7 mm`修正为实际坐标。动态捕获成功后
直接使用捕获中心、显示本次动态黄点且不应用固定补偿。T3～T5直接使用固定
机械O点，只有T6进入CAP并允许PB27动态捕获。T3～T5选择后先不限时等待固定
视觉连续3帧合法，随后显示`VISION OK`；必须再按确认键才启动。等待阶段不计时，
提前按键不启动也不进入FAULT。

K230屏幕把最近一次实际发送的距离用52号大字显示，其余有效状态、置信度、
序号、UART发送结果、捕获进度、零点像素和请求序号使用22号小字。

旧蓝牙协议、服务及对应主机测试已经从主工程删除；UART0 SysConfig配置仍在，
但`main.c`中的T3 CSV实现已经编译期停用。旧陀螺仪解析器仍为未接入业务的
历史源码。

## 当前底盘与平衡任务

- 八路X0～X7使用`PB20/PA24/PB25/PB26/PB10/PB14/PA17/PA7`直接GPIO，
  黑线低电平有效；
- 底盘方向使用`PB17/PB19/PA16/PB24`，TIMG0在PA12/PA13输出双路PWM；
- 左轮由TIMG8 PA26/PA27硬件QEI计数，右轮由PA14/PA25 GPIO中断译码；
- TIMG6提供10 ms控制节拍，ISR只累计待处理周期，速度PID、循迹和安全判定
  均在主循环执行；有控制积压时不进入WFI，也不刷新OLED；
- T2为394 mm/s巡航、800 mm/s²、2000 mm/s³，15.00 s起沿同一S曲线减速到
  100 mm/s并开放A线宽线识别；任意4路及以上连续3个10 ms采样后主动刹车，
  20.00 s仍未完成则超时。大误差循迹Kp为2.25，小误差Kp=1.0、Kd=0.5和
  八路位置权重保持不变；极端首拍轮速目标为738/50 mm/s，没有18 s定时停车，
  正常完成仍只由A线触发；
- T4恒定请求208 mm/s，T5/T6恒定请求230 mm/s，均保持最大300 mm/s²、
  800 mm/s³，不再在8.0 s二次请求加速。三项任务均不设自动停车时间，也没有
  B/A终点标志或宽线停车；运行中只能通过复位键或安全故障停车；
- T4/T5/T6正常循迹差速上限为100 mm/s，每个10 ms控制周期最多变化20 mm/s；
  前进速度超过20 mm/s后为内侧轮保留至少20 mm/s目标，左右轮目标平均值仍等于
  当前S曲线前进速度。按6141.592 mm赛道模型，T5/T6恒定230 mm/s的理论一圈
  时间约27.27 s，距30 s上限约2.73 s；该数值尚未经过实车验证；
- T4/T5使用固定O点，T6使用本轮动态捕获点；三项任务共用轴角PD、加速度
  前馈和120 ms视觉新鲜度保护。首次正向加速采用80 ms规划加速度预瞄，
  预瞄附加量限制为64 mm/s²，对应额外前馈角不超过4.30°；初次加速归零后
  自动关闭；恒速方案没有第二次请求加速。运行页显示本轮滤波坐标最大正偏差和
  最大负偏差，格式为`P+xxx.x N-xxx.x`，单位mm；该统计只用于观察，不因
  超过±10 mm进入FAULT。故障或复位仍同步制动底盘并停用X42。

陀螺仪业务仍不接入；旧解析器源码只作历史保留。

当前T3诊断版使用K230新鲜位置/速度反馈：先以`-20.50°`固定角启动，随后由
独立的正向PD接近`+5 cm`。任一新鲜原始位置进入`+46.5～+52.0 mm`即认定
正向段完成并开始负向参考，不增加速度门限；用户已确认当前T3运行稳定且
该完成结果正确。最终参考到达`-50 mm`后，只有连续5个新鲜原始位置均在
`-52～-47 mm`且滤波`|v|<=20 mm/s`才完成T3；任一帧越界或超速都会清零
稳定计数。球若仍在`-49 mm`
右侧且`|v|<=15 mm/s`，连续2帧启用`+1.50°`负向补偿并保持到`-49 mm`或
负向速度达到`-25 mm/s`。本诊断版删除T3的5000 ms总运行超时，但保留视觉
新鲜度、X42通信/跟随、机械边界、复位和急停保护；正向
`Kp=0.250、Kd=0.500`，负向`Kp=0.250、Kd=0.200`。T3～T5把球放到固定
机械O点并等待连续3帧合法视觉后进入READY，再按确认键启动；T6先等待原始单球
候选稳定后开放捕获，完成15帧捕获且TI收到连续3帧合法动态坐标后进入READY。
T6随后复用T5整圈底盘剖面和T4/T5滚球闭环，动态捕获点在控制器中对应`x=0`。
最终确认瞬间若120 ms视觉新鲜度不满足，只返回不限时放球等待，不进入FAULT；
任务启动后的视觉过期仍保留安全故障。

小球X轴把摆杆物理刻度12.5 cm处定义为`x=0`：远离合页为正方向，朝合页为
负方向。该小球坐标与齿条以机械下限为零点的软件坐标相互独立。

当前齿条软件坐标以人工确认的机械下限为0 mm：机械下限绝对伸长约22.5 mm，
水平位置绝对伸长约37.4 mm，对应软件位置14.9 mm；约52.0 mm绝对伸长会出现
脱齿，因此29.5 mm只作为硬边界，正常命令限制在1.0～28.5 mm。
实机方向验证采用协议字节定义：`direction=0x00`时齿条上升，
`direction=0x01`时齿条下降，不再使用容易受观察方向影响的顺/逆时针表述。
回平阶段使用5 RPM、加速度档30；任务3暂时仍使用20 RPM、加速度档100。

以下时间辨识轨迹仅为历史诊断，当前`main.c`不再调用：

```text
TASK3_REVERSE_FRICTION_DIAGNOSTIC = 0
TASK3_TIMING_CALIBRATION          = 1

任务启动：命令齿条到8.9 mm
x >= +50.0 mm：记录P=启动至该帧的时间，立即命令19.9 mm
x <= -50.0 mm：记录N=反向命令至该帧的时间，立即命令14.9 mm
4500 ms：保持/返回14.9 mm；两个事件齐全后等待电机反馈到位
5000 ms：仍缺事件或未到位则FAULT
```

上述历史辨识版只接受任务启动后的新序号有效帧，并使用`Task3TimingResult`
记录P/N事件；它曾在OLED显示P/N时间、速度和5000 ms故障超时。这些显示、
4500 ms完成检查和5000 ms故障超时均不属于当前参与编译的T3运行路径，不能
据此判断当前控制器行为。

当前步进电机服务先查询`0x1F`版本，再逐条等待停止、使能、清零和位置命令
的`0x02`接收确认。每条位置命令都先轮询`0x3A`状态；`Prf_TF`置位后读取
`0x36`实时位置，到位后继续按20 ms查询节拍交替读取状态和位置。只有到位位
有效且编码器换算位置在目标±0.3 mm内，命令才进入机械到位状态。UART1使用
64字节独立接收队列，发送整帧超时20 ms，查询回包超时20 ms，位置命令遇到
正在进行的查询时延后至回包后2 ms发送。协议错误、接收溢出、使能丢失、
堵转保护、命令应答超时或位置到位超时均立即进入故障。OLED处于任务菜单、
放球、捕获或READY等待页时，单次健康查询超时只累计并按20 ms周期
重试，允许人工不限时停留；明确的失能、堵转、负位置和硬角度越界仍立即故障。
进入回平或正式运行后恢复单次查询超时即FAULT。历史开环轨迹仍有
自己的5000 ms常量，但当前`main.c`调用的T3闭环诊断版不再使用总运行超时。

当前T2参数修订已通过独立`line_drive_service`主机测试，逐10 ms回归得到

按用户要求没有运行CCS Build，需由用户手动编译。此前构建

## 生成文件边界

`H_BallBalance_MSPM0G3507.syscfg` 是板级配置源文件。`ti_msp_dl_config.c/.h`、
启动文件和链接文件由SysConfig/SDK构建流程生成，不作为手工修改点，也不提交
`Debug`或`Release`构建产物。

## 操作约束

比赛版OLED显示任务选择、必要准备提示、运行计时和完成/故障状态。当前
T3时间辨识版额外显示P/N及两个目标处速度；T4/T5/T6运行页额外显示本轮
最大正、负滤波偏差，故障页保留该峰值和冻结时间。运行页每2秒刷新一次，
内部任务计时仍按毫秒推进，状态切换、完成和故障页仍立即刷新；降低刷新频率
只减少同步整屏刷新出现次数，不消除单次刷新占用。其他调试数据必须通过独立
编译开关启用。

## 当前T3操作

1. 断电时人工把齿条放到22.5 mm机械下限。
2. 上电后确认OLED显示`HOME / RACK LOW`。
3. 按确认键，系统依次停止、使能、四字节清零并移动约379脉冲到水平位置。
4. `LEVEL`结束并进入菜单后选择T3。
5. 按确认键进入`PLACE T3`，把钢球放到物理O点；未放稳时可不限时等待，
   提前按确认键不会启动或进入FAULT。
6. OLED自动显示`READY T3 / VISION OK`后再按确认键，任务和计时才同时启动；
   运行中复位键会立即停止并解除步进电机
   使能，确认机构静止后才能人工放回机械下限。
7. 观察K230：红点随球移动，默认黄点保持在机械O点。OLED的`P`是任务启动
   至首次进入`+46.5～+52.0 mm`正向完成区的毫秒数，`N`是开始负向参考至
   首次进入`-52～-47 mm`且速度合格的毫秒数；同一行的`V`为该帧计算的
   有符号速度，单位mm/s。
   横线表示对应事件未发生。
8. 告诉后续会话P、N、V+、V-、正向最大位置、最终位置、进入DONE或人工复位
   所需时间、最终控制角和X42命令/测量位置。若长期不收敛，按复位键停止，
   不允许机构无看护运行。
