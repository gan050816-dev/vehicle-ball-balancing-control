## 7. 两套坐标系

### 7.1 齿条坐标

```text
rack_position = 0 mm  ↔ 人工确认的22.5 mm机械下限
rack_position = 14.9 mm ↔ 37.4 mm绝对伸长，摆杆水平
```

齿条软件坐标只表示相对机械下限的位置，不能与小球坐标混用。

### 7.2 小球X轴

```text
摆杆物理刻度12.5 cm处 = O点 = x 0
远离合页方向            = +X
朝向合页方向            = -X
```

实机观察：齿条上升时小球向合页方向运动，即向`-X`运动；齿条下降时小球
向远离合页方向运动，即向`+X`运动。K230像素坐标必须先标定并转换到这套
物理X轴，不能直接假设摄像头像素增长方向就是`+X`。

## 8. X42步进电机最终采用方案

### 8.1 驱动器和协议

| 项目 | 当前采用值 |
|---|---|
| 驱动板 | X42_V1.3（停产版） |
| 驱动固件 | Emm5.0 |
| 物理接口 | TTL串口 |
| 波特率 | 115200 bit/s，8N1 |
| 电机地址 | 2 |
| 细分 | 16细分，按3200脉冲/圈换算 |
| 校验/帧尾 | `0x6B` |
| 清零命令 | 四字节`02 0A 6D 6B` |
| 控制方式 | 绝对位置模式，命令同时规定速度和加速度 |

本机实物确认的协议方向字节：

```text
direction = 0x00 → 齿条上升
direction = 0x01 → 齿条下降
```

当前绝对位置服务的软件零点位于机械下限，所有合法目标都是非负坐标，因此
位置帧保持`direction=0x00`，目标变小时由驱动器按绝对坐标反向。实机已确认
齿条上升、下降方向均符合预期。用户最新确认当前没有观察到齿轮打滑，本阶段
按“无打滑”作为工作假设；这不是独立位移测量证据，仍需用重复到位和人工
齿条位置检查验证。

### 8.2 回平流程

用户已经确认：每次上电前都会在断电状态下手动把齿条放到22.5 mm机械下限。
上电后的非阻塞流程已改为通信反馈确认：

```text
发送停止并等待0x02接收确认
  → 至少等待50 ms
发送使能并等待0x02接收确认
  → 至少等待100 ms
发送四字节清零并等待0x02接收确认
  → 至少等待100 ms
以5 RPM、加速度档30移动到14.9 mm（约379脉冲）
  → 等待0x02接收确认
每20 ms轮询0x3A状态
  → Prf_TF到位后读取0x36实时位置
  → 编码器换算位置在14.9±0.3 mm内
进入READY和任务菜单
```

软件已拆分“命令已发送、驱动器已确认、电机轴已到位”。UART1 ISR只写
64字节有界队列，解析和状态机在主循环运行；整帧发送超时20 ms，控制应答
超时100 ms，查询回包超时20 ms，每条位置命令到位超时2000 ms。位置命令若遇到
正在进行的状态查询，会保留最新目标并在查询回包后至少2 ms发送，避免命令
粘连。到位前每20 ms查询`0x3A`；到位后按同一查询节拍交替读取`0x3A`和
`0x36`，持续检查使能、`Cgp_TF`堵转保护和编码器位置。`E2/EE`、接收溢出、
使能丢失、堵转保护或任何超时均进入FAULT，并由应用所有状态立即执行安全
停机。T3阶段离散命令若遇到上一条控制应答或查询未结束，会用单槽保留最新
目标；连续跟踪模式最短80 ms发送一次，目标变化小于0.3 mm不发、单次最多
变化1.5 mm，并只要求每个中间目标收到`Receive`。T3控制器输出角度，以上
毫米阈值仅在步进执行器适配层内部使用。状态和实时位置继续交替
轮询；跟踪开始500 ms后，编码器与最新已发送目标相差超过3.0 mm并持续
400 ms会进入FAULT。T3完成由小球连续5个新帧的位置/速度条件决定，退出
跟踪后发送停止命令保持当时位置；当前闭环诊断版没有总运行超时，历史开环
诊断模块自己的5000 ms常量不参与`main.c`当前T3路径。

上述离散回平和连续跟踪流程已通过主机测试和CCS构建，尚未通过实物UART
验证。第二代X42S手册明确支持运动中以新位置命令打断旧命令并平滑过渡，
但同时把它列为第二代新增能力；当前实物为旧X42_V1.3/Emm5.0，因此该能力
必须通过`Receive`、`E2/EE`、动作连续性和编码器跟随实测确认。`READY`
表示电机编码器轴位置到位，不是独立齿条传感器测量；当前按用户确认的
“未观察到齿轮打滑”事实，把编码器位置作为齿条位置代理。

## 9. 上电、按键和当前操作

### 9.1 通用流程

1. 断电时人工把齿条放到22.5 mm机械下限。
2. 上电后确认OLED显示`HOME / RACK LOW`，此时不放钢球。
3. 按确认键，系统执行停止、使能、清零和自动回平。
4. 等待`LEVEL`结束并进入T2～T6菜单；T1图传由K230-B和上位机独立操作。
5. 根据任务完成小车对位、放球、捕获或图传准备。
6. 按确认键正式启动任务和计时。
7. 运行中按复位键会停止新增动作、发送停止并解除步进电机使能；确认机构
   静止后才能人工把齿条放回机械下限。

## 11. K230-A视觉闭环最终方案

### 11.1 输入和捕获

K230-A只识别钢球中心，不负责识别摆杆O点。T3～T5统一使用修正后的固定
机械O点，不执行PB27捕获；只有T6把球放到要求保持的任意位置后执行动态捕获。

最终协议至少需要：

- 沿摆杆方向的小球坐标；
- 识别有效标志和置信度；
- 帧序号；
- TI接收时间或可用于新鲜度判断的时间信息；
- 明确的帧头、长度、字节序和校验。

当前已冻结钢球状态帧V1，复用已成功案例的帧结构：

```text
A5 5A 10 08 flags sequence x_lo x_hi conf_lo conf_hi time_lo time_hi checksum
```

- 总长度固定13字节，115200、8N1，当前源码每20 ms发送一次；
- `flags bit0`为识别有效，`bit1`为正式标定完成，`bit2`为多候选；
- `x`是有符号16位小端，单位0.1 mm，范围限制为`-150.0～+150.0 mm`；
- `confidence`是0～1000的无符号16位小端数；
- `time`是K230 `ticks_ms`低16位，只用于识别K230侧冻结和延迟分析；
- `checksum`是从命令到载荷末尾所有字节的8位累加和；
- 无目标仍发送心跳，但`VALID=0`、`x=0`、`confidence=0`，TI忽略坐标。

K230-A主程序保存在`D:\eletri\k230\main.py`。连接固定为K230
GPIO9/UART1_TX到MSPM0 PB3/UART3_RX；双向时PB2/UART3_TX到K230
GPIO10/UART1_RX，并共地。

捕获时只接受合法且新鲜的帧，先收集10～20个稳定样本，剔除异常值后用中值
或平均值生成本次锁定坐标。任务运行后不能被后续捕获操作意外覆盖。

当前实现由TI发送`0x90`捕获请求，K230收到请求后才开始采集。具体采用15帧
中心像素中值：置信度至少0.65、单目标、15帧极差不超过3 px；K230通过
`0x11`结果帧返回请求序号、状态和零点像素。TI只接受当前等待序号，成功后
进入READY；2秒内没有形成稳定窗口则停留在CAP等待重试。TI UART3 ISR只写
128字节有界环形队列，解析在主循环执行；请求TX采用非阻塞检查和100 ms
超时。K230状态帧`flags bit3`表示本次目标零点有效。

MSPM0准备任一任务时先发送零载荷命令`A5 5A 91 00 91`。K230收到后取消
未完成捕获、清除动态目标有效标志，并切回固定机械O点。用户已经确认固定
黄色O点和现有橙色`+5 cm`位置准确。当前主程序在固定模式连续取得15帧
单一有效球后，一次性锁存黄色O点和橙线像素，并先生成固定基础坐标：

```text
x_base = (x_zero - x_ball) × 5 / (x_zero - x_plus_5)
```

`x_base>=0`原样输出，黄色O点、正方向坐标和`+5 cm`橙线均不改变。负方向
先保留此前已经形成当前K230显示/UART值的固定标定，再按用户最新毫米实测
关系反算实际刻度尺位置：

```text
y_current_mm = 0.6898 × x_actual_mm - 2.8626
x_actual_mm = (y_current_mm + 2.8626) / 0.6898
```

该拟合只用于负方向。黄色O点固定为`0→0`；O点到首个实测点`-10 mm`连续
连接，从`-10 mm`起严格使用反算式。实际`-50 mm`对应修正前当前K230值
`-37.3526 mm`，绿色`-5 cm`线据此反定位。固定线锁存后不再读取当前球框
宽度重算，因此同一次上电运行中不会漂移。T6动态捕获仍直接使用捕获中心和
当前1 cm球框比例，不应用固定锚点或上述负向修正。
K230仍发送原13字节状态帧，MSPM0协议无需修改；锁存完成前固定模式状态帧
不置有效，避免把未标定的0坐标交给TI控制。固定模式校正结果仍同时进入屏幕
显示和UART坐标，不只用于屏幕标线；新毫米拟合版当前只完成本地静态、主机
测试和构建验证，尚未部署到K230，不能把本地结果记作实机标定完成。

K230屏幕显示最近一次实际发送的数据：距离使用52号大字；识别有效性、
置信度、帧序号、UART发送状态、捕获进度/结果、零点像素和请求序号使用
22号小字。模型检测方框、框上置信度和ROI边框不再绘制；当前钢球中心使用
半径5像素红点，固定机械O点或15帧X/Y中心中值捕获点使用半径8像素黄点。
红点随球移动，当前模式的黄点保持不动；TI协议仍只传输横向X，不增加Y字段。
锁存完成后，`+5 cm`橙线和`-5 cm`绿线持续绘制在固定像素列，只覆盖有效
ROI；即使当前短时未识别到球，两条线也保持原位置。T6动态捕获模式不显示
固定参考线。K230重启后需要重新完成15帧固定标定锁存，T6动态目标也需重新
捕获。

### 11.2 不直接逐帧驱动电机

K230坐标不断变化是正常现象。不能“每收到一个坐标就排队发送一条电机命令”，
否则视觉延迟、串口积压和电机响应时间会使控制使用过时状态。采用：

1. UART ISR只把字节写入K230-A专用有界环形队列。
2. 主循环解析帧，只保存带序号和接收时间的最新有效状态。
3. 重复帧、异常跳变和过期帧不进入控制器。
4. 对位置做中值或一阶低通；只用相邻新鲜帧和实际时间差估算球速。
5. 当前控制器在每个新K230帧更新，位置EMA系数0.5，速度使用跨2帧的
   实际时间差并再做0.5 EMA。
6. 每个控制周期只消费最新状态，新角度目标覆盖旧目标，不能重放旧坐标。
7. X42目标最短80 ms发送一次，变化小于0.3 mm不发，每次最多变化1.5 mm。
8. 中间目标逐条等待`Receive`但不等待逐点到位；500 ms宽限后持续400 ms
   超过3.0 mm编码器跟随误差即FAULT。

### 11.3 控制符号

定义：

```text
e_x = x_target - x_predict
v_ball = 小球沿+X方向的滤波速度
```

当前位置外环直接生成相对平衡角：

\[
\theta_{raw}=-K_p e_x+K_d v_{ball}
\]

\[
\theta_{cmd}=\operatorname{clamp}
\left(\theta_{raw},-28.65,+14.32\right)\text{ degree}
\]

符号解释：

- `e_x>0`表示球需要向远离合页方向运动，因此齿条先下降。
- `v_ball>0`表示球已经向远离合页方向运动，因此齿条上升进行制动。

T3在固定角克服启动摩擦后，由角度PD完成接近和负向控制：

```text
0 → 固定-20.50°启动
  → 预测位置达到接管条件后用角度PD接近+50 mm
  → 原始坐标进入+46.5～+52.0 mm后立即切换目标，不限速度
  → 从该帧起角度PD连续追踪-50 mm
  → 连续5帧原始位置位于-52～-47 mm且滤波|V|<=20 mm/s → 完成
```

当前源码正向默认`Kp=0.250、Kd=0.500`，负向默认
`Kp=0.250、Kd=0.200`，`Ki=0`。
主程序不再接入蓝牙运行时调参；Kp、Kd和其他T3参数后续直接修改源码并重新
编译。控制器不输出齿条距离；步进服务
只在协议边界把相对角度换算为旧X42绝对位置命令。

### 11.4 处理电机响应延迟

闭环前分别测量：

- 发送位置命令到齿条开始运动的时间；
- 齿条开始运动到达到目标的时间；
- 发送反向命令到机构实际反向的时间；
- K230曝光、推理、串口发送到TI收到完整帧的总视觉延迟。

当前第一版先采用120 ms预测延迟：

```text
x_predict = x_filtered + v_filtered × T_delay
```

进行短时预测。连续120 ms没有新的有效状态时停止使用旧位置并命令相对
平衡角`0°`。视觉失效不作为成功；当前T3诊断版等待人工复位，不再由总运行
时限转为FAULT。

K230小球位置外环可以修正轻微比例误差和回差，但不能把严重丢步、电机轴与
齿轮打滑、齿条卡死或脱齿当成普通位置误差。X42内部闭环也不等于齿条实际
位置闭环。受机械结构限制，当前方案不能增加齿条直线位移传感器；后续以
X42电机编码器位置作为齿条位置代理。用户最新确认当前未观察到齿轮打滑，
因此不把打滑作为本轮故障来源；但编码器位置仍不是齿条实际位移的独立证据。
软件检查串口应答、目标—编码器位置偏差、到位、堵转和超时，但无法检测轴后
传动松动或齿条跳齿，实机重复到位检查仍保留。

### 11.5 T4～T6前馈和视觉反馈实施方向

T4～T6共用一个“保持目标位置”的滚球控制器：T4/T5目标为固定机械O点，
T6目标为本轮动态捕获位置。底盘循迹模块生成平滑的基础速度轨迹，并直接
提供规划纵向加速度；循迹左右差速修正不作为前馈输入。
滚球控制命令采用：

\[
h_{cmd}=14.9+h_{ff}-K_p e_x+K_d v_{ball}
\]

\[
h_{ff}=K_{ff}\,a_{plan}(t+T_{lead})
\]

其中`Kff`为实测前馈系数，`Tlead`为齿条相对底盘加速度的提前时间。前馈负责
抵消可预测的起步和减速惯性，视觉PD只修正摩擦、地面、轮速和循迹造成的
剩余误差。初版不加入积分、陀螺仪融合、在线辨识或自适应控制。

底盘采用平滑起步、路段中期恒定基础速度、评分标定点附近不突变速度的方式。
到达B点或完成一圈重新通过A点时，先锁存评分时刻，再在视觉闭环仍工作的
条件下平滑减速并回到水平；不能在评分事件发生时立刻停止步进电机，使齿条
停留在任意前馈位置。

当前主工程已经生成并接入：

1. 只在新视觉帧到来时更新的相对位置观测器、120 ms过期和异常跳变保护。
2. T4/T5固定O点以及T6动态捕获点的轴角PD和规划加速度前馈。
3. 八路循迹、双轮速度闭环；T4恒定请求208 mm/s，T5/T6恒定请求230 mm/s，
   三项任务不设自动停车时间，只能由复位或安全故障停车。正常循迹差速上限
   100 mm/s，每10 ms最多变化20 mm/s，前进速度超过20 mm/s后内侧轮目标至少
   20 mm/s，左右轮目标平均速度保持当前S曲线前进速度。
4. T6捕获成功回执后的视觉状态清空和新动态帧门控，防止固定O点旧帧启动。
5. 视觉、X42、命令拒绝、丢线、堵转和复位的底盘/步进联合安全停止。
6. T4/T5/T6按本轮目标零点记录滤波位置最大正偏差和最大负偏差；OLED运行页
   与故障页显示`P+xxx.x N-xxx.x`，该统计不参与FAULT或停车判断。

原闭环接入基线曾通过主机测试和CCS构建，但当前取消自动停车后的源码未执行
CCS编译；37.4 mm水平重复性、T6动态目标误差、实际通过A点时刻、前馈系数
和PD参数均没有主工程实车验证。后续仍按架空
方向检查、无球故障联动、单次低风险运行和逐项调参的顺序验证。

## 12. 当前安全边界

- 上电前必须人工确认机械下限；否则软件坐标和上限全部失去物理意义。
- 正常齿条目标只能在1.0～28.5 mm之间；29.5 mm脱齿边界禁止越过。
- 52.0 mm绝对伸长附近不得继续上升，也不做破坏性边界验证。
- 新位置目标必须同时受速度、加速度和单周期变化量约束。
- 视觉、K230和步进电机链路均不得无限等待；UART0当前无日志业务和中断负载。
